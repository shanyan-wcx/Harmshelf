# 完善播放器minibar拖拽与全屏转场

## Goal

让播放条与全屏播放器形成连续、可交互的空间转场：HdsTabs minibar/非 Tab 播放条
向上拖动时全屏页面跟手展开，松手后完成展开；直接点击播放条时从条形态变为全屏；
全屏左上角按钮按反方向缩回播放条。

## Background

- 当前 HdsTabs minibar 的原生展开/收起通过 `MyNavigation` 的三个回调同步到
  `MiniBarState`，`onMiniBarAnimationStart` 已能得到动画开始时的样式，结束回调
  没有操作序号。
- 当前 `PlaybackMiniBar.canOpenPlayer()` 把 `animating` 当作不可交互条件，导致动画
  中没有按照结束状态执行操作；本任务要求动画开始即采用目标状态的交互语义。
- 当前全屏播放页通过 `bindContentCover` 挂载 `playBuilder()`。现有
  `geometryTransition` 绑定未产生可见的封面变形，点击时全屏内容会突然出现。

## Requirements

### R1. Minibar 状态与交互时序

- HdsTabs 展开/收起动画开始时，立即把 `expanded` 和点击/命中逻辑切换到目标状态。
- 动画态只用于处理过期回调和内容同步，不能禁止目标状态本来允许的点击操作。
- 保留过期结束回调保护，不能因快速反向操作把最终状态覆盖成旧状态。

### R2. 向上拖动打开全屏

- HdsTabs minibar（折叠圆形封面、展开条）和非 Tab 播放胶囊条都支持向上拖动打开
  全屏播放器。
- 拖动过程中，全屏页面从播放条位置向上、向外逐渐展开，视觉上跟随手指；不能先
  突然显示完整全屏页面再等待松手。
- 松手后继续完成打开动画，不因松手导致回弹到播放条；原有播放条 controls 的点击
  逻辑保持不变。
- 折叠 minibar 的普通点击仍由 HdsTabs 负责展开，向上拖动才进入全屏拖拽流程。

### R3. 点击与关闭转场

- 直接点击展开 minibar 或非 Tab 播放条时，播放条自然变形为全屏播放页，禁止默认
  上下滑入、透明度淡入或模糊式出现。
- 点击全屏播放页左上角收起按钮时，全屏页面反向缩小到当前播放条位置，动画完成后
  才关闭全屏内容。
- 不同设备形态和播放源（网络、本地、无封面）都使用同一套交互时序，不出现封面
  突然跳到中心或内容晚到的问题。

### R4. 兼容与回归

- 保留 HdsTabs 原生 minibar 展开/收起、非 Tab 条最大宽度和现有左右边距。
- 保留快退、播放/暂停、快进、关闭播放器、播放状态和全屏页所有面板逻辑。
- 不新增依赖，兼容项目最低 API 26。

## Acceptance Criteria

- [ ] 展开/收起动画一开始，播放条的命中与点击语义立即等同于目标状态；快速反向
      操作后状态和内容仍稳定。
- [ ] 从折叠/展开 minibar 或非 Tab 条向上拖动时，全屏页面随拖动逐步展开；松手后
      自动完成全屏；普通点击不经过透明度/模糊过渡而完成条到全屏的变形。
- [ ] 点击全屏左上角按钮时，全屏页面反向缩回播放条，完成后才恢复播放条交互。
- [ ] 封面、标题、副标题、控制按钮和三种封面来源在转场期间不闪现、不延迟补齐。
- [ ] DevEco CLI API 26 debug 构建成功，任务归档后工作区干净。

## Out of Scope

- 不重写全屏播放页的播放控制、背景、弹出面板和播放业务状态。
- 不调整 HdsTabs 原生 barWidth/miniBarWidth、底部 Tab 布局或非 Tab 条的既有尺寸策略。
- 不通过新增依赖或系统服务实现拖拽。
