# 统一修复弹出面板内容高度与顶部间距

## Goal

让内容型弹出面板按实际内容高度显示，消除标题栏下方因固定高度和百分比高度造成的异常空白；需要滚动的列表面板继续保留稳定的可滚动高度。

## Confirmed Facts

- `Add.ets` 的“确认添加”面板使用 `height: 457`，builder 根节点是 `Scroll().height('100%')`，内部表单内容没有声明高度。
- `Setting.ets` 的添加/编辑服务器面板使用固定 `388`，builder 根节点是包含百分比高度 `Scroll` 和加载层的 `Stack`。
- `EpisodeDetail.ets` 与 `LibraryItemDetail.ets` 的举报面板使用固定 `348`，复用的 `ReportPanel` 根节点及内容层使用百分比高度。
- 其他内容型面板已经使用 `SheetSize.FIT_CONTENT` 且根节点没有百分比高度；播放列表、收藏、剧集、书签等列表面板使用 `SheetSize.MEDIUM`，内部列表需要可滚动，不属于本次强制收缩范围。
- 所有面板内容根节点目前保留 `top: 8`，该间距继续保留。
- 官方 Sheet 文档规定 `SheetSize.FIT_CONTENT` 根据 builder 根节点布局自适应，且根节点不应使用百分比高度；居中/跟手弹窗在 API 22 及之前低于 `320vp` 会使用最小高度，但从 API 23 开始低于该值按实际自适应高度生效。本项目最低 API 为 26，因此本次 FIT_CONTENT 不会被系统强制抬到 `320vp`。

## Requirements

1. 将“确认添加”、添加服务器、编辑服务器、举报内容等非列表固定高度面板改为 `SheetSize.FIT_CONTENT`。
2. 移除这些 FIT_CONTENT builder 根节点及其直接布局层的百分比高度依赖，确保 sheet 可以从实际内容测量高度。
3. 保留每个面板内容根节点的 `top: 8`，并保留必要的底部安全留白、按钮逻辑、加载状态和滚动能力。
4. 不改变 `SheetSize.MEDIUM` 列表面板的滚动行为和既有内容间距。
5. 检查所有 `bindSheet` 实例，确认没有遗漏其他内容型固定高度面板。

## Acceptance Criteria

- [x] 确认添加面板打开后，首个输入框与标题栏下方只保留 `8vp` 内容间距，面板底部没有固定高度产生的额外空白。
- [x] 添加服务器、编辑服务器、举报内容面板按内容高度显示，标题到首个控件间距保持 `8vp`。
- [x] 所有表单/确认类按钮仍可点击，加载动画仍能显示且不改变面板交互。
- [x] 播放列表、收藏、剧集、书签等需要滚动的 MEDIUM 面板高度和滚动行为不变。
- [x] DevEco 构建通过，源码改动已完成提交准备。

## Out of Scope

- 不调整标题栏文字、按钮尺寸、面板背景材质、面板圆角或底部留白数值。
- 不把有长列表的 MEDIUM 面板改成 FIT_CONTENT。
- 不修改播放页内容布局或业务回调。

## Open Questions

无。用户已确认统一按内容实际高度修复，并保留需要滚动的列表面板。
